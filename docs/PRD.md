# 面试复盘 App —— 产品需求文档（PRD）

> 版本：v1.0（MVP）
> 状态：已评审
> 读者：Android agent（Android Studio）、后端 agent（IntelliJ IDEA）、产品/技术总监（Claude Code）
> 本文档是**唯一事实源**之一，与技术方案 `tech-spec.md` 配套。任何功能/接口变更必须先改文档再改代码。

## 1. 背景与目标

### 1.1 背景

- 作者是 2027 届应届生，正处在秋招中，求职方向为 Android 客户端开发（也想补后端短板应聘全栈岗位）。
- 每场面试后需要复盘：回听录音、整理被问的问题、总结答得不好的地方、针对不懂的点补课。
- 当前这个流程是手动的（录音 → 人工转写 → 人工总结），效率低、容易遗漏。
- 同时，秋招越来越看重「实际 AI 辅助开发经验」，本项目的开发过程本身就是证据。

### 1.2 项目目标

做一个**面试复盘 App**，把「录音 → 转写 → AI 总结 → 追问补课」这条链路自动化：

1. 用户用**系统录音机**录下整场面试（后台长录音，无需 App 常驻）。
2. App 从系统读取录音文件，上传到自建后端。
3. 后端调云端 ASR 把录音转成文字。
4. 后端调 LLM 生成**结构化复盘总结**。
5. 用户可就总结或转写内容**继续追问**，AI 针对性讲解不清楚的点。
6. 多场面试的录音统一管理（列表、详情、播放、打标签、删除）。

### 1.3 成功标准（MVP 完成定义）

- 端到端跑通一次完整流程：导入一条真实录音 → 上传 → 转写 → 出总结 → 追问一句得到回答。
- 后端所有接口可用 `curl`/Postman 独立验证通过。
- Android 客户端在真机上能完成「导入 → 查看 → 追问」全流程。
- 代码仓库有清晰 README + 架构图 + AI 协作过程记录（devlog）。

### 1.4 非目标（明确不做，防止范围蔓延）

- **不在 MVP 内**：多用户/登录、云端部署、App 内录音（实时 AudioRecord 采集）、跨录音聚合分析、本地 whisper、Redis 缓存。
- **永远不做**：录音的公开分享/社交功能、支付。

## 3. 核心用户场景（User Story）

| # | 场景 | 优先级 |
|---|---|---|
| US-1 | 面试结束，用系统录音机录好音。打开 App，从录音列表里选这条，点击导入。App 上传后自动转写，我过一会儿能看到文字稿。 | P0 |
| US-2 | 转写完成后，App 自动生成结构化总结（被问的问题、我的回答要点、可改进处）。我快速浏览总结回顾这场面试。 | P0 |
| US-3 | 复盘时对某个回答有疑问，我在详情页打字追问（如「这道『Handler 原理』我答得对吗？应该怎么答更好」），AI 结合我的转写内容针对性回答，回答逐字流式显示。 | P0 |
| US-4 | 我有多场面试的录音，在列表页看到每条的状态（转写中/已完成/失败）、标题、时间，能播放回听、改标题、打标签、删除。 | P0 |
| US-5 | 转写失败时（如音频格式不支持），我能看到失败状态和原因，而不是静默失败。 | P1 |

## 4. 功能清单（MVP）

### F1 录音导入

- **描述**：读取系统录音机 App 的本地录音文件，作为复盘素材来源。
- **实现要点（产品层）**：
  - 主路径：列出 `MediaStore.Audio` 中的录音文件（按时间倒序），用户点选。
  - 兜底路径：提供「手动选文件」入口（SAF `ACTION_OPEN_DOCUMENT`），用户从任意位置选音频文件。
- **验收标准**：
  - 能列出系统录音机里最近的录音（文件名、时长、日期可见）。
  - 点选后能成功上传到后端并生成一条记录。
  - 无录音权限或文件读取失败时，给出可理解的提示。

### F2 录音上传

- **描述**：把选中的音频文件上传到后端。
- **实现要点**：Multipart 上传；大文件（50–100MB）要有进度展示；上传失败可重试。
- **验收标准**：上传 50MB+ 文件不超时；有进度条；失败能重试。

### F3 自动转写（ASR）

- **描述**：后端对上传的音频调云端 ASR，生成转写文本。
- **实现要点**：上传后**异步**转写，不阻塞接口；状态机：`转写中 → 已完成 / 失败`；失败记录原因。
- **验收标准**：
  - 上传后立即返回记录 id，转写在后台进行。
  - 客户端能查询到转写状态；完成后能看到转写全文；失败能看到原因。

### F4 AI 结构化总结

- **描述**：转写完成后，用 LLM 对转写全文生成结构化复盘。
- **总结需包含（固定结构）**：
  1. **面试整体概览**：考察了哪些方向/模块。
  2. **被问问题清单**：逐条列出面试官问的问题。
  3. **我的回答要点**：针对每个问题的回答核心。
  4. **可改进处**：答得薄弱或不确定的点。
  5. **下一步补课建议**：建议复习的知识点。
- **验收标准**：总结按上述结构输出；转写完成后自动触发；失败可手动重试。

### F5 追问对话

- **描述**：用户就某条录音的内容与 AI 进行文本对话，问不清楚的点。
- **实现要点**：
  - 对话上下文 = 该录音的转写全文 + 总结 + 历史对话消息。
  - 回复**流式**（SSE）逐字显示。
  - 对话严格限定在**单条录音内**（不同录音的对话互不串）。
- **验收标准**：追问能得到结合「我的录音内容」的针对性回答；流式显示不卡顿；历史消息可回看。

### F6 录音管理

- **描述**：对录音记录做轻量 CRUD。
- **功能点**：列表（含状态、时长、日期、标签）、详情（转写 + 总结）、本地播放回听、改标题、打标签、删除。
- **验收标准**：增删改查正常；删除后列表同步；播放用本地文件流畅回放。

## 5. 非功能需求（NFR）

| 维度 | 要求 |
|---|---|
| 用户规模 | 单用户，无鉴权 |
| 部署 | MVP 后端本地运行（`0.0.0.0` 监听），手机连局域网访问 |
| 上传 | 支持 ≥50MB 文件，有进度与超时处理 |
| 转写 | 异步，状态可查，失败可见 |
| 对话 | 流式，单条录音内隔离 |
| 密钥安全 | ASR/LLM 的 API key 不硬编码、不提交 Git |
| 数据 | 录音文件存后端本地磁盘，元数据存 MySQL |
